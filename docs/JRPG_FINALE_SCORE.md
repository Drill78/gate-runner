# 最后长阶 · 两个原创 JRPG 主题

2026-09-08。根据真人反馈，将最后长阶拆成「空灵的朝圣」与「紧张的反抗」两套原创主题。主神战使用反抗主题的专属前奏版。曲调、和声、段落和 MIDI 编排均为本轮新写，没有截取用户提供的音乐，没有沿用旧曲加速处理。

曲目音量是 `MusicTrack.volume` 的建议值，另乘玩家的总音量。三首均以约 −18 LUFS 的成品响度交付，避免切曲突然变响。当前文档定义音频契约，播放选择、暂停和续播由游戏的音乐模块负责；制作脚本不修改游戏逻辑。

## 星穹长阶 · 云上的誓歌

`stair-heaven`：E 大调 / 升 C 小调，6/8，四分音符 90 BPM。每小节 2 秒，8 秒前奏后进入 64 小节、128 秒循环。节拍呈两组缓缓流动的三连分组，避免战斗进行曲的重拍压迫。

主旋律以 E–F♯–G♯–B 的上行展开，随后用下行回答与九度延伸收束。和声采用大七、九和弦、转位低音与悬挂音；竖琴交替改变音区和分解顺序。钢琴先独奏，长笛与双簧管轮流接句，随后独奏小提琴、弦乐群、无词合唱与轻圆号展开。低鼓与定音鼓只在较宽广的段落轻轻托住脉搏。

| 时间       | 段落与配器                                       |
| ---------- | ------------------------------------------------ |
| 0–8 秒     | 远处合唱、单音钢琴与竖琴，保留较大的声部间距     |
| 8–40 秒    | 钢琴唱出朝圣主题，竖琴与延迟进入的木管回答       |
| 40–56 秒   | 长笛接句，钟琴留下高处的微光                     |
| 56–72 秒   | 降低织体密度，双簧管与钢琴回到更近、更私人的空间 |
| 72–88 秒   | 弦乐接过旋律，合唱逐渐打开                       |
| 88–120 秒  | 弦乐、合唱与圆号展开，保持空灵和宽阔             |
| 120–136 秒 | 收回到木管和稀疏点缀，属和声返回循环起点         |

## 碎冕之战 · 向神挥刃

`crown-fracture`：E 小调 / G 大调，4/4，144 BPM，72 小节、120 秒完整循环。从第一小节就有明确的弦乐快速音型、切分低音与鼓组，适合第 99 关直接进入紧张战斗。

这首使用新的十六小节反抗主题。短促的上行起句与下行回答交替，主旋律保留可唱的长音；内声部用十六分音符拨弦与八分音符弦乐制造推进，不把所有声部都写成同一个节奏。钢琴低八度强化旋律，圆号在第二遍进入。中间缩减为钢琴与双簧管，再转入更宽广的 G 大调副歌；最后用合唱、铜管与全鼓组展开，回到 E 小调。

| 时间               | 段落与配器                                               |
| ------------------ | -------------------------------------------------------- |
| 0–40 秒            | 新激战主题、快速弦乐内声部、切分钢琴、指弹低音与摇滚鼓组 |
| 40–53.333… 秒      | 钢琴和双簧管的短暂喘息，鼓组退到较轻的半拍律动           |
| 53.333…–66.666… 秒 | G 大调副歌，长线弦乐与圆号拉开情绪                       |
| 66.666…–80 秒      | 回到主旋律，恢复推进                                     |
| 80–106.666… 秒     | 无词合唱、弦乐、圆号与鼓组共同展开                       |
| 106.666…–120 秒    | 回归主调，管风琴低层补充终局感并接回循环                 |

## 黎明的裁决 · 光与誓言

`dawn-judgment`：前 24 秒为专属前奏，之后是同一反抗主题的完整战斗编排。

前奏先以 E 大调的远处合唱、钢琴、竖琴和钟琴展开，长笛短暂回忆朝圣主题。16 秒后和声逐渐转暗，通过 C、A 小调与 B7 指向 E 小调，拨弦、定音鼓与最后的鼓花逐步增加紧张感；24 秒进入完整激战主题。它不是把第 91–98 关的整段曲目简单拼到前面，而是为主神单独写的十二小节开场。

24 秒后的段落对应 `crown-fracture` 整体向后平移 24 秒。二者为同一音乐主题与编排，细微的人性化起音差异来自每声部的确定性时间/力度变化；没有改变速度或音高。循环从 24 秒开始，前奏不重复。

## 音源与制作方法

本轮用 **GeneralUser GS 2.0.3** 采样音源，通过 **FluidSynth 2.6.0** 分轨离线渲染，再用 NumPy/SciPy 完成混音。钢琴、竖琴、钟琴、长笛、双簧管、小提琴、大提琴、弦乐群、合唱、圆号、低音、鼓组和定音鼓均采用相应音色。这是原创作曲的采样器演奏，含第三方乐器采样，不是从零振荡器合成，也不是本次邀请真人演奏或录唱。

音源来自 [S. Christian Collins 官方项目](https://github.com/mrbumpy409/GeneralUser-GS)，[作者许可](https://github.com/mrbumpy409/GeneralUser-GS/blob/main/documentation/LICENSE.txt)允许用其制作并发布私人或商业音乐录音。完整音源仅留在本地制作目录，不打包进游戏。作者对早期部分采样来源的说明保留在许可原文中。

FluidSynth 来自 [官方 2.6.0 Windows 发布](https://github.com/FluidSynth/fluidsynth/releases/tag/v2.6.0)，下载归档 SHA-256 与 GitHub 发布摘要核对一致：

```text
fluidsynth-v2.6.0-win10-x64-cpp11.zip
817262deacaa748edb3af6731dffe1766b00146790becfccc949a9f701e76681

GeneralUser-GS.sf2
9575028c7a1f589f5770fccc8cff2734566af40cd26ed836944e9a5152688cfe
```

没有全局安装程序，没有下载未知来源可执行文件，没有把音源或工具加入游戏运行依赖。编码复用项目既有 FFmpeg 7.1。

每个声部有少量确定性的力度与起音变化；长音合唱与弦乐有表情控制。分轨分别设定高通、空间长度和湿声量，低音与鼓组保持靠前、合唱与竖琴更远。母带处理包括频段整理、保守的软饱和、响度归一化与真峰值约束。尾部乐器和混响尾音回写到实际循环主体起点，最后用极短的边界平滑处理减少接缝；前奏保持一次性的因果顺序。

## 本地重制与核验

入口：`scripts/generate-jrpg-finale.py`。依赖 Python、NumPy、SciPy、上述 SoundFont、官方 FluidSynth 与现有 FFmpeg。

```powershell
C:\Python314\python.exe scripts/generate-jrpg-finale.py `
  --fluidsynth artifacts/music-jrpg/tools/fluidsynth/fluidsynth-v2.6.0-win10-x64-cpp11/bin/fluidsynth.exe `
  --soundfont artifacts/music-jrpg/tools/GeneralUser-GS.sf2 `
  --ffmpeg artifacts/music-tools/imageio_ffmpeg/binaries/ffmpeg-win-x86_64-v7.1.exe
```

`--reuse-stems` 复用本地已生成的干声 WAV 做重混；修改音符、乐器或表情之后应完整重渲染。`--validate-only` 只回读成品并检查响度、长度、峰值与循环，不重写 MP3。

- `artifacts/music-jrpg/*-score.json`：音符、起音、时值、力度和控制器事件。
- `artifacts/music-jrpg/<曲目>/<声部>.mid`：分轨 MIDI；采用固定 960 ticks/秒时钟，90 / 144 BPM 的音乐网格在脚本中转换为秒。
- `artifacts/music-jrpg/<曲目>/*-dry.wav`：采样器分轨，不带引擎自带混响。
- `artifacts/music-jrpg/*-master.wav`：编码前的 32 位浮点立体声母带。
- `artifacts/music-jrpg/*-decoded.wav`：最终 MP3 的实际回读，用于核验有损编码后的结果。
- `artifacts/music-jrpg/jrpg-music-report.json`：完整技术报告；归档版本复制到 `docs/data/music-jrpg-report.json`。

制作脚本逐首校验采样长度、双声道、零削波、目标响度、真峰值及循环接缝；制作前后对既有 MP3 逐一 SHA-256 对照。客观测量能发现导出问题，音色偏好与情绪效果仍以玩家的实际试听为准。
