# 1.2.3 兵潮与军势防御审计

本次让后期兵力提供有上限的生存收益，普通道路逐步形成兵潮，精英至少保留开场出招窗口。最终版本的种子734三职业带钥匙／不带钥匙六条自然路线均通过100关；另一个种子1743的无钥匙骑士也通过。敌人的血量、攻击与数量由关数和难度决定，不根据玩家当前兵力反向抬高。

模拟仍能熟练横移、瞄准和连续使用技能，因此这些结果证明存在可通关路线，不能当作真人胜率。成熟构筑仍能快速清场，本次没有把每只普通怪都做成需要长时间攻击的血包。

## 兵力仍然是对数加成

兵力使用尾数和指数保存。当前输出乘数为 `1 + log2(1 + 兵力 / 12)`，随后乘军势盟约；武器、符文和职业伤害在另一层计算。`2.55 × 10^136` 不等于同样倍数的攻击，它约提供451倍兵力基础输出倍率。

实装防御：`L = max(0, log10(兵力) - 3)`，`军势减伤 = 0.40 × L / (L + 24)`。与原护甲相乘：`总减伤 = 1 - (1 - 装备护甲) × (1 - 军势减伤)`。

| 兵力 | 军势减伤 |
| --- | ---: |
| 1,000及以下 | 0% |
| 10^6 | 4.44% |
| 10^12 | 10.91% |
| 10^24 | 18.67% |
| 10^42 | 24.76% |
| 10^60 | 28.15% |
| 2.55×10^136 | 约33.90% |
| 趋于极大 | 逼近40%，不会达到无敌 |

计算只读取指数和尾数的对数；不还原超大整数，不遍历每个士兵。无兵力护甲的三职业获得相同的相对承伤改善，骑士装备护甲继续独立生效。

## 敌方防御：原有机制与此次调整范围

读取实施前代码发现，普通精英与章节首领本体基础护甲为零。普通黑甲盾卫有22%常驻护甲。举盾期间从正面打入时额外减伤70%；守护召唤物存活时，本体额外减伤45%。天使化在碎翼前减伤80%，金身是可击碎的最大生命10%护盾及2.2秒无敌窗口，两者不能混称为固定护甲。

演出承伤预算与减伤是独立机制：有复燃的灰烬之王首命12秒、复燃18秒；登神王首命24秒、第二命30秒；主神72秒；其他异化章节首领8秒；其余天使首命6秒。预算累计允许伤害随实际战斗时间释放，还限制单次承伤至最大生命12%（主神3.2%）。这些限制防止跳过演出，不代表受到所有攻击都减少同一百分比。

实装普通精英护甲按六轮为18%／22%／28%／32%／36%／40%，91—100不再额外叠加这层精英护甲。第16—90关的普通精英另有前三秒的累计承伤进度预算：每秒最多释放最大生命的三分之一，并限制保护期内的单击伤害。三秒结束后完全退出这段保护，不再保留单击上限；常驻精英护甲仍然有效。第一轮及长阶不追加这项保护。

这项保护来自实测反馈：只增加HP和护甲时，六个固定成熟构筑精英样本中有五个仍在首次攻击前被击杀。增加短暂开场窗口后，最终六个样本均能出1—2招，随后正常结束，避免用数倍额外血量拖住重铸后的弱构筑。

## 兵潮和额外收益

首轮前、中、后三章每波2／3／4个单位，首关头三波仍只出一个；第二至第六轮每波依次5／6／7／8／9个，跨轮不会回落。每章原有波数仍为8／10／12，因此第六轮每个普通战斗基础敌群合计72／90／108只，另算关末精英、精英道路斥候和召唤物。91—100保持首领直接战，不插入普通兵潮。

| 轮次 | 每波基础数量 | 普通怪HP附加倍率 | 章节首领HP附加倍率 | 关末普通精英HP附加倍率 | 精英护甲 | 攻击附加倍率 |

| II，16—30 | 5 | 1.20 | 1.12 | 1.25 | 22% | 1.12 |

以上是乘在原关数曲线外的附加倍率，不替换原来第三、第六轮的陡坡。每轮后两章的普通怪HP再乘1.1／1.2；第一轮后两章攻击再乘1.04／1.08。长阶91—98保留原HP，攻击乘1.24；99原HP再乘1.15、攻击乘1.24；100不增加这两项，继续作为较宽松的演出收束。

含正常正向选项的门有一次随机稀有增益机会：随机值低于1.5%时将一条正向选项改成×5；1.5%—7%为×2；7%—15%为较大加法。加法在实际显示前按当时军势换算，约为88%—110%的援军。不是每条通道各滚15%；没有正向选项的门、固定禁门试炼和首个教学门不参与。

原本每只普通怪即使从侧边离开，也会造成全局血伤。新增兵潮单位从侧边漏过不扣血，真正接触才造成原碰撞40%的伤害；独立接触间隔为0.25秒。原来的先锋及远程怪仍保留原规则。

新增行尸的生命为本波先锋的38%—50%，不主动远程攻击，每只相隔0.17秒。每波全部新增行尸的金币、经验和吸血总权重只有一只完整单位的0.35，按人数均分，金币与经验的小数先累计再发放整数。九只怪不会变成九倍经验和九倍吸血。

## 验证方法与复现

新脚本 `node scripts/v123-balance.mjs` 默认运行固定构筑测试。所有战斗使用实际引擎及既有150毫秒观察决策的横移、瞄准和技能程序。没有注入额外生命、免伤、金币或符文，也不会自动花复活币。

- `--suite=curve`：检查真实stats与极大指数的有限性。
- `--suite=focused`：三职业旧自然46／76关构筑在普通与精英道路的对照、76关不移动控制、91入口自然构筑直接挑战99／100、独立99开发预设。
- `--suite=opening`：三职业普通与困难模式从开局走完15关。
- `--suite=natural`：三职业从正常无尽开局走到100关，使用实际地图、菜单和商店。
- `--keys=both`（默认）：无尽分别运行购买钥匙与不购买钥匙的路线；也可选`yes`或`no`。
- `--trials=elite`：固定测试只运行三职业46／76关共六个精英。
- `--label=baseline` 或 `--label=final`：将输出保存为不同文件，保留代码哈希以便区别实施前后。
- `--classes=ranger`、`--seed=734`：选择有界样本。固定构筑仍使用原种子734的真实存档，开发者入口与新路线使用传入种子。

固定构筑资料来自上一轮真实路线保留下来的45／75／90关存档。99／100测试明确把91入口构筑搬到目标关，未伪造此前8关的强化，它是控制变量检查，不是新自然路线。站桩对照仍会攻击和使用技能。模拟通过率只描述这些确定性样本，不能解释为真人胜率。

旧基线使用提交`0afe7c1`的`lib`目录副本，由`ENGINE_ROOT`指定；未切换或回退共享工作区。每份JSON记录加载引擎的SHA-256。`initial-implementation`和`after`资料是中间版；最终数值以`final`与`final-elite`为准。

## 结果：精英窗口、站桩与最后两关

最终代码中，第46关测试精英约75.2万HP、32%护甲；第76关约481.8万HP、40%护甲。使用上一轮保留的同一自然构筑，无需额外回血，三职业均通过：

| 职业 | 46关精英交战／出招 | 76关精英交战／出招 |
| --- | --- | --- |
| 骑士 | 3.60秒／1次 | 4.35秒／2次 |
| 游侠 | 3.30秒／1次 | 3.10秒／1次 |
| 法师 | 3.80秒／1次 | 3.70秒／1次 |

固定76关普通道路的移动样本均通过且生命承伤为0；站桩骑士失败，游侠和法师仍可通过，但分别损失108和163生命。增加密度提高了处理敌群和位置的要求，同时保留群攻构筑与熟练操作的收益；不能据此声称所有毕业构筑都会被普通道路逼到残血。

同一份91入口自然构筑直接挑战99关，三职业约55—56秒通过；直接挑战100关均约73秒，且该组无生命承伤。较弱的99开发预设通过时间为骑士55.6秒、游侠56.7秒、法师67.1秒，仍体现输出和技能机制差异，100保持完整但较宽松的演出。

完整路线和24个固定样本在最后移除“精英三秒后的残留单击上限”之前已经完成。该修正只解除保护期结束后的额外限制，未增加敌方强度；之后针对最终代码单独重跑上述六个精英，均通过。报告没有将这两次不同代码哈希的测试冒称同一次运行。

另做了8个关数节点的独立性检查：仅把兵力由`2.55×10^4`改成`2.55×10^136`，敌人HP、护甲、攻击、数量、初始阵位与异化全部相同。军势防御计算还检查到`Number.MAX_SAFE_INTEGER`指数，结果始终有限。
