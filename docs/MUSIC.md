# 灰烬之门 · 原创背景音乐

四首均为原创、无歌词的程序化器乐合成。旋律、和声、节奏、弦乐音色、鼓组与空间响应全部由 `scripts/generate-music.py` 生成，没有使用第三方音乐片段、音频采样或真人演唱。游戏直接加载已经生成的 MP3，不需要运行合成脚本。

## 曲目与编配

| 文件                         | 曲名       | 场景      | 速度 / 小节       | 精确解码时长 | 文件大小       |
| ---------------------------- | ---------- | --------- | ----------------- | ------------ | -------------- |
| `public/audio/normal.mp3`    | 铁与誓言   | 普通战斗  | 112 BPM / 24 小节 | 51.428571 秒 | 1,029,943 字节 |
| `public/audio/boss.mp3`      | 王座之前   | 章节 Boss | 136 BPM / 24 小节 | 42.352948 秒 | 848,653 字节   |
| `public/audio/final.mp3`     | 灰烬终誓   | 最终 Boss | 164 BPM / 32 小节 | 46.829274 秒 | 937,992 字节   |
| `public/audio/forbidden.mp3` | 门后的低语 | 神秘关卡  | 80 BPM / 16 小节  | 48.000000 秒 | 961,504 字节   |

总计 **3,778,092 字节，约 3.78 MB**。全部采用 44.1 kHz、双声道、LAME 160 kbps CBR MP3，并保留 Xing/LAME 无间隙播放元数据。

前三首共享一段原创 D 小调八小节旋律，和声围绕 Dm–B♭–C–F–A 展开。普通战以掌根闷音五度吉他、拨弦贝斯和八分踩镲推进；中段将主题交给类似拨弦扬琴的音色，让循环有呼吸。Boss 战提高速度，吉他改用更密集的切分与十六分节奏，鼓组增加底鼓和过门。最终战的速度和密度最高，加入连续十六分吉他、双踩、叠八度主旋律与更持续的合唱质感背景音，保持最强压迫感。

《门后的低语》使用独立旋律，以半音张力、低音持续音、钟声、反向拨弦与稀疏战鼓构成阴森空间。它保留低音吉他和鼓的实体感，节奏留白明显多于前三首。

## 音色与制作

- **电吉他：** 模拟拨片激发的多泛音琴弦，以根音、五度和八度构成三弦和弦；加入轻微失谐、拨片噪声、琴桥频谱、非对称过载与箱体滤波。失真以双倍采样率处理，再降采样。左右双轨的音色和起音略有差别。
- **贝斯：** 低音琴弦的基频与衰减泛音叠加，带拨弦起音和轻度饱和，支撑吉他节奏。
- **鼓组：** 独立合成底鼓、军鼓、闭镲、开镲、叮叮镲、吊镲和三档通鼓。底鼓包含降调鼓膜与槌头瞬态，军鼓包含鼓腔和响弦噪声；力度与极小的时间偏移避免完全机械重复。
- **中世纪旋律：** 以维埃尔琴、木管和拨弦扬琴为音色方向，使用泛音、共鸣、弓弦/气流噪声及轻微揉弦。背景合唱为无字元音共振峰合成 pad，没有歌词或语音。
- **空间与母带：** 各乐器分组混音，配置短房间、长残响与交叉延迟；母带去除直流、保留低音空间，并使用温和饱和控制瞬态。

## 循环方式

每首从完整拍点开始并在整段小节结束处回到起点。音符释放、镲尾、延迟和混响跨过结尾时，按环形方式写入开头；混响采用周期卷积，不额外追加静音，也不以整段淡出掩盖循环。母带首尾另有 1 毫秒的局部端点修整。

播放器可直接循环解码后的整个音频缓冲区，不需要设置额外裁切点。MP3 携带编码延迟与尾部填充信息；此次 FFmpeg 解码验证中，四首的样本数均与母带完全相同。目标浏览器的解码、切曲、暂停和静音行为应在播放器集成时确认。

## 已执行的音频检查

下表测量对象是最终 MP3 的解码结果，而非只测量编码前的 WAV。

| 曲目       | 综合响度    | 真峰值     | 削波样本 | 首尾样本差 / 常规相邻变化 P99 |
| ---------- | ----------- | ---------- | -------- | ----------------------------- |
| 铁与誓言   | −17.99 LUFS | −6.60 dBTP | 0        | 0.041                         |
| 王座之前   | −18.00 LUFS | −6.75 dBTP | 0        | 0.084                         |
| 灰烬终誓   | −18.00 LUFS | −7.95 dBTP | 0        | 0.065                         |

四首响度差为 0.01 LU，编码后真峰值均低于 −5.8 dBTP，保留了充足余量。母带首尾样本差为零；压缩后首尾差小于歌曲常规相邻样本变化 P99 的 11%。接缝附近的能量允许随下一小节的下拍起鼓增加，因此不能把短窗能量变化直接当作接缝噪声。

脚本断言覆盖：40–60 秒时长、44.1 kHz 双声道、解码样本数匹配、零削波、真峰值低于 −1 dBTP、目标响度误差不超过 0.5 LU、接缝变化阈值，以及所有文件合计小于 8 MB。最终四首均通过。验证是离线信号与编码检查，音色听感仍可根据试玩反馈调整。

## 重新生成与验证

依赖 Python、NumPy、SciPy，以及支持 `libmp3lame` 的 FFmpeg。本次使用 Python 3.14、NumPy 2.3.4、SciPy 1.16.3 和 FFmpeg 7.1。编码器通过独立工具目录中的 `imageio-ffmpeg 0.6.0` 提供，没有加入项目运行依赖。

```powershell
python scripts/generate-music.py --ffmpeg "C:\path\to\ffmpeg.exe"
```

脚本默认将最终 MP3 写入 `public/audio`，WAV 母带、编码回读文件及 `music-report.json` 写入系统临时目录中的 `ashen-gates-music`。可通过 `--work-dir` 指定工作目录，避免把大体积中间文件放入仓库。

```powershell
# 只重新生成一个场景
python scripts/generate-music.py --ffmpeg "C:\path\to\ffmpeg.exe" --only final

# 复用工作目录中的母带，再次校准响度和编码
python scripts/generate-music.py --ffmpeg "C:\path\to\ffmpeg.exe" --encode-only

# 不改变 MP3，只进行回读检查并生成报告
python scripts/generate-music.py --ffmpeg "C:\path\to\ffmpeg.exe" --validate-only
```

报告记录每首的样本数、时长、响度、峰值、接缝统计、文件大小及 SHA-256。编排使用固定随机种子；改变音符、节奏或音色参数后，应重新生成并执行相同检查。
