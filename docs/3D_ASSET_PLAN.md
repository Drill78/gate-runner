# 灰烬之门 3D · 美术与模型生产清单

1.1 补充：资产范围同时覆盖长夜无尽。黯化、血月、空冠首领需要可辨认的材质／身体模块与独立动作、特效；合葬首领需要两位原型融合后的连贯轮廓与对应模型，不能仅靠换色和光环。双王、三首领与分段连战需要独立出生点、镜头和血条布局；可招募首领需要友方识别、跟随姿态与援击动画。具体遭遇谱系以 `lib/endless.ts` 和 `docs/V1_1_DESIGN.md` 为准。

配套主文档：[3D_REBUILD_HANDOFF.md](3D_REBUILD_HANDOFF.md)。日期：2026-09-08。

**本表全部属于待制作计划。当前原型没有这些可复用的最终 3D 模型。** 姓名、敌人类型和技能身份取自 1.0 原型；新的造型、材质和演出是重构设计建议。每一种出现在游戏空间中的角色、怪物和实体物件都必须有资产映射，同类多实例可合理共享模型。

## 1. 全套美术共同标准

统一使用强轮廓、漫画式大块明暗、手绘材质、沉重中世纪器物与有节制的异质器官。三幕使用不同光色和腐化语言，重要主体优先拥有视觉焦点。

先完成概念设定与比例，再建立模型、UV、贴图、骨骼、动画、运行时材质和特效；以游戏内效果作为最终判断。允许基础骨架复用与模块化装备，独特轮廓、关键肢体、武器和材质仍需按角色设计。

每种角色或强敌的成套交付包括：正侧背设定、关键装备说明、可编辑模型、运行导出、完整动作、游戏视角效果、新风格立绘与图鉴裁图。建模应覆盖实际可见的背面、侧面和阴影，不能只在立绘正面成立。

## 2. 三位可玩角色

| 内容 ID / 身份 | 轮廓与重设计方向 | 模型部件与材质 | 必要动作与反馈 |
| --- | --- | --- | --- |
| `knight` · 誓约骑士，阿德里克·维恩 | 宽肩、修补长盾、破损战袍；成熟面容留有疲惫感，沉默而可靠 | 板甲、布袍、剑、铆补盾、腰带和护手；旧钢、骨白布、暗红衬里、少量旧金 | 待机、行进与横移、移动中攻击、举盾、受击、技能、死亡、胜利；誓约剑气与出剑动作同拍 |
| `ranger` · 灰林游侠，希尔雯·暮叶 | 修长但有力量，兜帽、精灵耳、斜披风和大弓弧；警惕的观察姿态 | 分层皮甲、布披风、灰木弓、弓弦、箭袋、箭；冷绿、灰木和磨损皮革 | 待机、行进与横移、拉弓/放箭、箭雨技能、受击、死亡、胜利；手、弓弦与箭挂点正确 |
| `mage` · 秘火法师，瑟兰·灰烛 | 瘦长成熟学者、层叠法袍、名字卷册、带禁忌痕迹的长杖；克制而危险 | 法袍、书册、长杖、饰扣、烛火容器；梅紫、墨黑、琥珀与微量冷蓝 | 待机、行进与横移、杖击/施法、秘火新星、召集队列、受击、死亡、胜利；施法不遮住角色与危险边界 |

三套立绘共享模型的脸部年龄、服饰切口、武器形状和饰物。角色在选人界面、战斗与图鉴中应是同一个人。至少交付三张主角完整立绘及适配头像；具体尺寸由新 UI 布局确定。

武器等级 25 不要求制作 25 套同形武器。先按原型名称阶段制作可辨识的装备外观阶段，并让等级提升由伤害、弹体与装备细节共同表达；外观分段规则记录在内容数据中。

## 3. 普通敌人、援军与队伍

| 资产 / 对应原型 | 造型与制作要求 | 动作 / 状态 |
| --- | --- | --- |
| 骸骨先锋 · `soldier` | 被旧军服包裹的骸骨士兵，破盾或断刃，头颅与胸腔可辨识 | 行进、攻击、受击、倒下/散落；肢体关节正常 |
| 黑甲盾卫 · `guard` | 封闭黑甲、大盾、收缩的头肩结构；与黑甲统领有军团关联但体量不同 | 行进、举盾、防御、攻击、受击、死亡 |
| 幽林弓手 · `archer` | 枯瘦长臂、残缺兜帽、弓和带腐木气息的箭袋 | 行进、停步拉弓、射击、受击、死亡 |
| 精英斥候 · 原型复用 soldier 行为 | 独立的轻装剪影、绑缚面罩与斥候装备；可以复用适合的骨架 | 快速行进、攻击、受击、死亡 |
| 铁誓援军 · commander 召唤的弓手 | 使用正式援军装备变体，明确与统领阵营一致 | 出现、入场、射击、受击、死亡 |
| 蚀月魂灯 · `guardianOf` / stationary | 骨笼或月冠灯架、悬浮灯芯、细长支架，实际可攻击物体 | 召出、悬浮、受击、破碎、退场；护佑连线与主人对应 |
| 我方代表性队员 | 至少骑士、游侠、法师队列各有合适的低成本模型/装备变化 | 跟随、移动、加入、消失/牺牲；与主角比例和画风一致 |

三幕可通过护甲部件、腐化部位与材质变体表达同种敌人的地域变化。模型清单应区分“独立造型”“装备变体”“共享骨架”。仅变色不能承担所有章节身份差异。

我方队员默认仍是兵力的视觉表达，不新增独立生命与 AI 规则。大数值兵力使用代表性队列，不创建数十亿个模型。

## 5. 五种章节首领

| ID / 名称 | 场景与邪性身份 | 模型重点 | 必须支持的招式与演出 |
| --- | --- | --- | --- |
| `watcher` 荆棘守望者 | 仍在守卫已死誓约的森林圣骑士；枝条从甲缝和身体内部生长 | 树根与重甲融合、枝角、古斧、根盾；生长方向有结构 | 入场、斧击、盾击、根墙生长、追猎标记、半血变化、死亡后根墙消退 |
| `wyvern` 岚翼古龙 | 被风暴圣脊和古老崇拜侵染的双足翼龙；伤翼仍能遮蔽道路 | 双足、两翼前肢、长颈尾、破膜、角骨；专用龙骨架 | 入场、翼展、呼吸、风刃、推击、龙息、侧翼龙焰、踏击、死亡；运动不能遮掉主要预警 |
| `lich` 蚀月巫妖 | 死去星体的祭司；骨面、悬月冠与空洞法袍 | 骨架、法袍、可分离星环、杖、灯挂点；漂浮层次明确 | 入场、星雨、召出两盏魂灯、护佑、吟唱、半血变化、死亡及灯的同步退场 |
| `oracle` 命运先知 | 被未来观测侵蚀的预言者；碎星盘、遮目仪式与异常环结构 | 法衣、仪式杖、星盘和漂浮饰件；面部焦点与异质细节独立设计 | 烙印、旧位置裂隙、镜像回声、星阵、阶段变化、死亡 |
| `king` 灰烬之王 | 神圣且令人畏惧的最终王权；光环与祭冠逐步破碎，露出王座内的空洞 | 焦黑重甲、旧金冠、巨剑、裂隙、圣性光源；三阶段形态可辨识 | 王座入场、火环、敕令吟唱、打断反应、陨火、交叉焚风、断界、70% / 35% 换阶段火墙、最终死亡与通关收束 |

最终王阶段应同时改变姿态、轮廓、材质焦点和招式演出。制作可切换部件或阶段形态，不能只把第三阶段模型整体变红或加大光圈。

困难双 Boss 是两位真实模型同场战斗：第一幕守望者 + 古龙，第二幕巫妖 + 先知。必须单独设计同屏站位、动作展开范围、目标标识与血条映射，尤其验证翅膀、星环、法袍和巨斧是否挡住另一位首领及危险路线。

## 6. 门、荆棘、危险区与可破坏物

| 资产组 | 必需模型 / 变体 | 状态与交互要求 |
| --- | --- | --- |
| 常规数值门 | 可组合的门框、立柱、基座、符文承载面；正收益与负收益材质变化 | 可缩放门洞与不同宽度；加减乘除标签清楚；通过与失效反馈 |
| 禁术红门 | 独立的红门/黑铁仪式门构件 | 保留门和数值，省略“必经红门”说明；五道连续门有清楚空间秩序 |
| 禁术秘门 | 窄门、异教雕刻、平方符文承载物、黑焰结构 | 显形、开启、通过、消散；符号与判定范围一致 |
| 荆棘障碍 | 至少直段、弯段、簇团、断枝、根冠等模块；真实弯曲枝条和尖刺 | 静态障碍也有体积、阴影与碰撞代理；不要用地面图标作为最终荆棘 |
| 守望者根墙 | 主根、横向盘根、荆棘枝与生长段 | 蓄力 → 生长 → 激活 → 枯萎；实际伤害边界可读 |
| 蛛网危险区 | 锚点、蛛丝网面、附着残骸与可见厚度层次 | 铺设、激活、消退；可用透明网片辅助，存在真实空间结构 |
| 石誓碎石/震击 | 多种碎石、凸起石板、裂隙边缘 | 预警、隆起、震击、落回/消散；地面贴花辅助边界 |
| 阴影裂隙 | 裂口边缘与内部深度几何，独立阴影/异质材质 | 裂开、持续、关闭；不会覆盖安全区与脚部判定 |
| 龙焰/王座火墙 | 火墙路径、焦土/岩块或裂隙骨架，配套火焰粒子 | 预警 → 起焰 → 燃烧 → 消退；粒子可用面片，路径和实体环境有空间对应 |
| 普通宝箱 | 箱体、盖、锁、铰链、金属包边 | 完整、受击、开盖/破碎、掉落、清理 |
| 兵装秘匣 | 与普通宝箱可辨识的武器匣或军资箱 | 受击与武器奖励反馈，模型与奖励类别关联 |
| 金币与可见战利品 | 钱币、钱袋、武器/补给等实际展示物 | 掉落、聚拢、拾取；重复实例合批或复用 |

模型形式不能强行改变规则。装饰尖刺伸出很远时，要控制模型尺寸或标清有效范围，不能让玩家凭视觉判断时频繁误判安全距离。

## 7. 武器、弹体、法术和遗物

- 主角剑、盾、弓、箭袋、箭、法杖、书册均有对应实体模型和挂点。
- 敌方飞斧、箭、实体陨石需要模型与旋转/飞行动作；星弹、火球、剑气和魔法轨迹可用合适的网格、材质与粒子组合。
- 护盾、暴击、穿透、爆裂、DOT、召唤、群体伤害分别有可区分的视听语汇，粒子数量受预算管理。
- 弹体增大既改变模型/特效可见范围，也同步反映判定；不要仅增大发光外圈。
- 35 项遗物至少制作统一画风的独立手绘图标；凡在商店或奖励场景以实体陈列的遗物，补齐相应模型。卡片中的图案可以是 2D 绘制。
- 神秘钥匙制作独立模型、拾取/购买展示与黑焰侵染反馈；未知效果的发现流程保持克制。

| --- | --- | --- |
| 荆棘边境 | 道路模块、断墙、石拱、古树、盘根、荆棘、残旗、墓石、圣龛与刑具 | 保留中路行动空间，侧面建立遮挡与纵深；城防和植物共用同一世界尺度 |
| 月蚀回廊 | 地砖、柱廊、破窗、拱顶残片、月纹祭器、星盘、镜面、烛台、布幔 | 形成真实柱距与前后层次；冷色焦点与幽暗通路有节奏 |
| 余烬王座 | 巨门、阶梯、王座、破圣像、焦柱、灰烬堆、熔金裂口、王庭旗帜 | 用尺度、光和建筑引导最终王；战斗区域边界保持清楚 |
| 主入口/选人 | 圣门、门扇、枢轴、雕刻、火盆、角色展示空间 | 开门有体积与光线变化；选人直接展示新角色模型及配套立绘 |
| 连线地图 | 三幕地形沙盘、关卡地标和可达连线表达 | 可读的路线图仍是核心；地标和环境由 3D 模型建立 |
| 商店 | 商贩摊位、货架、灯、金币与商品陈列 | 暖色休整空间，手绘商品与实体展示一致；NPC 如新增则独立列入资产范围 |
| 问号事件 | 祭坛、井、石碑、遗藏/书籍等七类事件所需陈设 | 共享场景模块，按事件更换真正对应的物件和焦点 |

道具套件按结构分类：建筑承重件、地面铺装、植被、祭祀物、生活物、战争残骸。每件物品有来源和用途，装饰密度由焦点和可读性决定。场景模块可复用，但三个章节不能只靠换一张背景或改颜色区分。

## 9. 动画与导出约定

角色基础动作建议使用稳定命名：`idle`、`move`、`strafe_left`、`strafe_right`、`attack`、`hit`、`skill`、`death`、`victory`。Boss 另有 `intro`、`phase_transition` 和以技能 ID 命名的动作；存在飞行/多足结构时建立专门动作集。

规则移动由模拟决定，默认不让动画根位移偷偷改变位置。武器、发射点、技能中心、受击点和脚底原点要有明确挂点。攻击动画标记用于同步声音和特效，实际伤害/计时由统一战斗事件提供。

每个主体检查：比例、法线、UV、贴图引用、透明度、蒙皮、关节拉伸、武器握持、披风穿插、脚底接地、动作切换、阶段部件、碰撞代理和资源释放。多足怪与古龙不能仅依靠通用人形动画完成。

LOD、三角面数、骨骼数、材质数、贴图大小和阴影成本在示范关实测后形成具体预算。不得以最终王或原型截图在开发机上流畅为依据，推定普通手机双 Boss 也符合预算。

## 10. 资产记录模板与完成状态

建议在新项目建立机器可读的资产目录，并为每项资产填写：

```yaml
id: boss_watcher
displayName: 荆棘守望者
contentId: watcher
status: planned
source: null
runtime: null
portrait: null
materials: []
animations: []
requiredAnimations: [idle, move, intro, attack, hit, root_wall, hunt_mark, phase_transition, death]
sockets: []
collision: null
lods: []
dimensionsMeters: null
sourceAndLicense: null
validationEvidence: []
```

状态顺序可以是 `planned → concept → modeled → textured → rigged → animated → integrated → verified`。静态道具按适用项跳过绑定和动作，但仍需运行时集成与验收。

阶段性统计分别报告“设计通过”“模型完成”“动画完成”“游戏内验证”，避免把生成过一张概念图统计成已完成一个角色。所有角色/强敌/物件的原型 ID 应能在清单找到映射；最终发布不应存在无说明的占位条目。
