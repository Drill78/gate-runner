# v0.5 战斗平衡验证

本次验证对应实体弹幕、章节 Boss 生命翻倍、禁术钥印与五连红门的最终版本。保持原兵力火力公式，没有为平方门增加高兵力衰减。完成 72 次移动远征和 12 次站定对照，全部从零遗物、武器 Lv1 开始，经合法路线、实际三选一奖励与商店构筑。

## 通关结果

| 移动通关数 / 8 | 骑士 | 游侠 | 法师 |
| -------------- | ---: | ---: | ---: |
| 职业协同优先   |    7 |    4 |    8 |
| 经济、兵力优先 |    4 |    2 |    4 |
| 无遗物         |    0 |    0 |    0 |

站定但正常释放职业技能的协同构筑，三职业均为 0/4。无遗物组同时禁止直接购买遗物和随机遗物商品；24 次远征最终遗物均为空。经济组仍会获得有效遗物，不等于故意构筑失败。

协同构筑有明确通关路径，游侠仍比另两职业更难。小样本中法师协同组全部通关，不能据此推断真实玩家胜率。完整分组摘要见 [CSV](balance-summary.csv)。

## 平方门前置与代价

- 稀有遗物「禁术钥印」只能在完成至少 4 层后的精英或章节 Boss 奖励中，以 12% 概率进入候选；玩家仍需选择它。普通奖励、商店和随机遗物来源不产出钥印。
- 持有钥印后，下一次精英战开启一次禁术试炼；每次远征最多一次，错过平方通道也不会再次生成。
- 试炼先经过五道全宽必经红门：减 18%、除以 1.30、减 22%、除以 1.35、减 25%。减法值在首次预览时依照前门结算后的预计兵力锁定，职业召唤与整数取整照常生效。
- 无召唤修正时，1,000 兵经过五道门后约剩 272 兵。随后出现平方、根号和加法的三选门；平方实际宽度 0.148，约占门组可用宽度的 7.6%，位置随机。
- 原火力倍率保持为 `1 + log2(1 + N / 12)`。没有额外的高兵力削弱，也没有 999 人上限；仅保留 JavaScript 安全整数保护。

72 次移动样本共选择钥印 12 次、开启试炼 10 次、实际通过平方门 9 次。一场试炼在到达最终门前失败。逐项检查这 9 次记录：均持有钥印，均按顺序通过了第 1 至第 5 道红门；没有重复开启试炼，没有达到安全整数上限。

成功穿过窄门后仍允许获得显著的兵力和火力收益。

## Boss 时长与周期伤害

章节 Boss 基础生命由 850 提升至 1,700，普通关底与精英关底基础生命保持 430 / 550。Boss 停留在屏幕上方，其攻击时钟与特色机制正常运行。

下表为协同构筑成功击杀章节 Boss 的平均交战秒数，不含此前波次和立绘登场暂停。各项只计算实际到达且完成击杀的样本。

| 章节 Boss |  骑士 |  游侠 |  法师 |
| --------- | ----: | ----: | ----: |
| 第一幕    | 13.01 | 22.49 |  9.51 |
| 第二幕    | 11.93 | 10.99 |  8.99 |
| 第三幕    |  6.63 | 10.47 | 12.69 |

周期强制伤害保留：宽限 22 / 17 / 17 秒，间隔 8 / 7 / 6.5 秒，首次原始伤害 10 / 16 / 20，后续每次追加 3 / 4 / 5。职业护甲与护盾正常生效；同帧击杀优先于周期伤害。

移动协同组中，骑士失败 1 次来自 Boss 常规攻击；游侠失败 4 次，其中 3 次来自王前波次、1 次来自周期伤害；法师无失败。经济组骑士第三幕平均击杀耗时 41.49 秒，明显高于协同组，周期伤害能对较弱输出施加压力。

强构筑仍可能迅速结束后期 Boss，骑士协同组第三幕尤其明显。本版保留这一构筑收益，未据此再次削弱兵力火力或追加隐藏缩放。若后续试玩仍认为后期缺乏压迫感，应分别评估 Boss 阶段机制与职业词条组合。

## 控制器与数据完整性

控制器每 150ms 决策，战斗每 50ms 推进，通过真实 `movePlayer` 按指针速度上限 4.8/秒连续移动。只读取已出现目标、公开预警和可见弹体；依据当前弹速、半径和目标移动预测瞄准。守望者举盾时采用侧翼射击，职业技能正常使用。

各取卡策略使用同一套路线规则：受伤时偏向休息、有足够金币时考虑商店，每幕通常至多选择一次精英；实际持有未使用的钥印且生命充足时优先进入可达精英。协同组与经济组在实际奖励提供钥印时优先选择，未预知未来奖励。

检查结果：无预装遗物、无非法奖励或路线、无无遗物组偷购遗物、无重复试炼、无超时；站定组移动距离为零。移动控制器在本样本中未受到实体弹幕命中，其轨迹判断明显强于普通触屏玩家。

本次没有浏览器点击、截图或真机触屏测试。模拟结果验证规则和构筑差异，不能验证手机上的手感、可读性或窄门命中难度，也不能作为真实玩家胜率。

## 复现与版本记录

移动样本每职业、每策略使用 8 个种子：`734 + i × 1009`，`i = 0..7`；站定组每职业协同策略使用前 4 个种子。

PowerShell 移动组：

```powershell
$env:RESULT_FILE = 'artifacts/balance-physical-moving.json'
npm run test:balance -- 8
```

站定对照：

```powershell
$env:STATIONARY = '1'
$env:MODE_FILTER = 'coherent'
$env:RESULT_FILE = 'artifacts/balance-physical-stationary.json'
npm run test:balance -- 4
Remove-Item Env:STATIONARY, Env:MODE_FILTER, Env:RESULT_FILE
```

运行会输出 JSON 与 CSV。脚本还支持 `CLASS_FILTER`、`PILOT_REACTION` 和 `ENGINE_ROOT`。本次原始结果和逐项分析保存在被 Git 忽略的 `artifacts/balance-physical-*.json` 中，提交的 CSV 包含最终 12 组摘要。采样完成后战斗源码仅作格式化，规则没有变化；结果保留采样时源码散列。

本版 58 项自动化测试、类型检查、静态检查和生产构建通过。测试覆盖实体弹体碰撞、穿透与次级效果、平方门前置、五道红门无法横移绕过、单次试炼、原兵力公式、商店边界和存档兼容。
