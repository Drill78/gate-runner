## 测试如何进行

所有远征从正常开局、零遗物、Lv1 武器开始，种子为 734 + i×1009，i 从 0 到 63。使用真实地图连接和三选一，不预装毕业装备，不读取未来敌人或奖励。控制器每 150ms 观察一次已出现敌人、门和已公布预警，使用真实每秒 1.45 单位的移动速度，不瞬移；模拟每步 50ms。瞄准最先越界的目标，在来得及的情况下比较当前门收益，并避开已知预警与荆棘。技能依照可见目标和剩余血量使用。

路线只比较当前可选节点，固定优先级：营火 → 宝库 → 普通战斗 → 商店 → 首个合法节点。营火在生命低于 75% 时治疗，否则锻造；商店缺血超过 20 时买药，然后买随机遗物（不选遗物组除外）和武器。合理构筑组在生命超过 80% 时可选献血事件，其余组离开。这是一条偏稳健、重视武器的路线，不能当作精英连战的基准。

合理选卡优先级如下。候选评分为 100−5×序号；低于 60% 生命时橡木之心 +60，9 层以前第一层血饮 +30，第一层盾锋 +35，已有盾锋时第一层誓言回响 +30。

- 骑士：bash → paladin → aegis → bulwark → steel → plate → vampire → vitality → mirror → army → thorns → recruit → bounty
- 游侠：hunter → quiver → keen → deadeye → steel → vampire → vitality → ricochet → mirror → army → ambush → recruit → bounty
- 法师：archmage → surge → echo → ward → steel → vampire → vitality → ember → mirror → army → summon → recruit → bounty

经济/兵力组优先通用遗物，其内优先钱币、号角、双生、战旗；没有这些时仍接受钢刃、血饮等，不故意送死。不选遗物组跳过战后遗物、商店遗物，但保留主动技、武器、门、宝箱和治疗。因此组间差异反映正常构筑路线差异，并非只改变一项变量的严格因果实验。

## 站桩对照与调校

审计智能体在最终骑士参数、月蚀缝隙修复前另外运行 128 个种子的移动/站桩对照：正常移动合理构筑 128/128、经济优先 55/128、不选遗物 0/128；完全不移动但正常选卡和放技能的合理构筑仅 1/128 存活（种子 60265），另两组均 0/128。不能称为数学上绝对无法站桩。该历史对照未因最后一次首领预警宽度修复重新运行；上方 64 种子表才是最终代码数据。

旧参数下所有 24 种子合理及弱构筑均能通关，好构筑无实际生命损失。采用敌人基础生命 110、幕首领 850、每层 ×1.34，修复弓手预警后明显增加持续输出要求。骑士技能盾从 24 改为 18，史诗额外盾从 30 改为 12，过门盾从每层 8 改为 6，盾锋每点护盾由 1% 改为 0.5%，降低长时间站桩能力。

## 可复现与边界

`npm run test:balance -- 64` 生成 `artifacts/balance-results.json`，包含全部种子、每层状态和最终遗物。摘要保存在 [CSV](balance-summary.csv)。可用环境变量 `CLASS_FILTER`、`MODE_FILTER`、`PILOT_REACTION`、`STATIONARY=1` 运行指定对照，详见脚本。不要把该模拟程序接入产品自动游玩。

它没有衡量真人反应、手指遮挡、不同设备帧率或视觉辨认时间，也没有穷尽所有路线/种子/六套构筑。首版验收采用机制测试、类型检查、静态代码检查和生产构建；没有进行浏览器点击或截图测试。实际试玩后优先观察每职业各幕死亡层、漏怪数、武器等级、受伤来源与过门收益，再针对数据调整。
